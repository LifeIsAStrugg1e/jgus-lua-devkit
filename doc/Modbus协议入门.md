# Modbus 协议入门(从零开始)

> **本文定位**:讲清楚 Modbus 协议本身——帧长什么样、寄存器是什么、功能码怎么用。
> 读完你就能看懂 `modbus.lua` 每一行在干什么。
> 屏幕固件侧的 Modbus 配置(22.BIN)是另一件事,见《晶兴Modbus开发指南.md》。

---

## 1. Modbus 是什么:一句话版本

**Modbus 就是"主站问、从站答"的一问一答串口协议。**

- **主站(Master)**:发号施令的一方,通常是 PLC、你的 Lua 模组。只能主站先开口。
- **从站(Slave)**:被问的一方,通常是 IO 模块、变频器、传感器。从站**从不主动说话**,只在被点名时回答。
- 总线上一根串口线挂多个从站,靠**从站地址**区分——就像喊"3 号楼注意"。

你的项目里:**Lua 模组是主站**(发读/写命令),**IO 模块是从站**(地址 1)。
图示:

```
 Lua 主站                       串口总线(485/232)
┌──────────┐   读寄存器?   ┌─────────┐
│ modbus.lua│ ────────────> │ 从站 #1  │──> 继电器/传感器...
│          │ <──────────── │ (IO模块) │
└──────────┘   回答:值是X  └─────────┘
```

## 2. 数据模型:Modbus 眼里的世界是四张表

Modbus 把每个从站的数据抽象成**四张表**,记住四张表就记住了一半:

| 表 | 官方名 | 读写 | 单位 | 现实对照 | 典型功能码 |
|---|---|---|---|---|---|
| **线圈 Coils** | 0xxxx | 可读可写 | 1 位(开/关) | 继电器输出、指示灯 | 01 读 / 05、0F 写 |
| **离散输入 Discrete Inputs** | 1xxxx | 只读 | 1 位(开/关) | 按键状态、限位开关 | 02 读 |
| **保持寄存器 Holding Registers** | 4xxxx | 可读可写 | 16 位(0~65535) | 设定温度、计数值 | 03 读 / 06、10 写 |
| **输入寄存器 Input Registers** | 3xxxx | 只读 | 16 位 | 传感器实测值(温度/电压) | 04 读 |

记忆法:**线圈=开关量,寄存器=数值量;Input=只读,Holding=可写**。

关键点:**一个 16 位寄存器 = 2 字节**,数值范围 0~65535,没有负数和小数——负数靠约定(如偏移 -100 存),小数靠约定(如 ×10 存整数),或 32 位浮点(占 2 个连续寄存器,字节序要和设备方约定)。

## 3. 帧结构:一次对话长什么样(RTU 模式)

Modbus RTU 一帧 = 4 段:

```
┌──────────┬──────────┬─────────────┬──────────────┐
│ 从站地址  │ 功能码    │ 数据         │ CRC16 校验    │
│ 1 字节    │ 1 字节    │ N 字节       │ 2 字节(低在前!)│
└──────────┴──────────┴─────────────┴──────────────┘
```

三个铁律:

1. **大端序**:所有多字节数值**高字节在前**。寄存器值 0x1234 发出去是 `12 34`,不是 `34 12`。
2. **CRC16 低字节在前**(`modbus.lua` 用 `crc16.check_crc16` 生成,它已按低字节在前排好)——和数据的"高在前"**正好相反**,这是 Modbus 最经典的坑。
3. **帧与帧之间靠静默分隔**:RTU 规定 3.5 个字符时间的空闲=上一帧结束。串口速率 9600 时约 4ms——所以接收要按字节流攒帧(你的 `parse_modbus()` 状态机干的就是这个)。

### 3.1 逐字节读一个真实例子

**主站问**:"1 号站,帮我读保持寄存器,从 0x0000 开始,读 2 个寄存器"

```
01    03    00 00    00 02    C4 0B
地址  功能码 起始地址  寄存器数   CRC16
```

**从站答**:"好,这 2 个寄存器的值分别是 0x000A 和 0x0014"

```
01    03    04       00 0A   00 14   xx xx
地址  功能码 字节数    寄存器1  寄存器2  CRC16
```

注意三点:响应里的**字节数(0x04)**告诉主站后面跟 4 字节原始数据;地址 0x0000 在请求里就是"从 0 号寄存器开始";数值全部高字节在前。

## 4. 功能码:8 个够用 95% 的场景

功能码就是"你想要我干什么"的动作编号:

| 功能码 | 动作 | 请求帧数据段 | 响应帧数据段 |
|---|---|---|---|
| 0x01 | 读线圈 | 起始地址(2B) + 个数(2B) | 字节数 + 位数据(每字节装 8 个位) |
| 0x02 | 读离散输入 | 同上 | 同上 |
| **0x03** | **读保持寄存器** | 起始地址(2B) + 个数(2B) | 字节数 + 寄存器数据(每寄存器 2B) |
| 0x04 | 读输入寄存器 | 同 0x03 | 同 0x03 |
| **0x05** | **写单个线圈** | 地址(2B) + 值(2B:`FF00`=开,`0000`=关) | 原样返回请求 |
| 0x06 | 写单个寄存器 | 地址(2B) + 值(2B) | 原样返回请求 |
| 0x0F | 写多个线圈 | 地址 + 个数 + 字节数 + 位数据 | 起始地址 + 个数(4B) |
| **0x10** | **写多个寄存器** | 地址 + 个数 + 字节数 + 寄存器数据 | 起始地址 + 个数(4B) |

加粗的 0x03/0x05/0x06/0x10 是你 `modbus.lua` 里实际用到的。下面每个配一个真实帧:

### 0x03 读保持寄存器(最常用)

```
请求:01 03 00 6B 00 03 xx xx    ← 读 1 号站,0x006B 起 3 个寄存器
响应:01 03 06 02 2B 01 06 00 00 xx xx
              ↑字节数6  ↑0x022B  ↑0x0106  ↑0x0000
```

### 0x04 读输入寄存器(读传感器)

请求/响应格式与 0x03 完全一样,只是读的是"只读表"。你代码里用它读 IO 模块的故障状态位。

### 0x05 写单个线圈(控制继电器)

```
开继电器:01 05 00 04 FF 00 xx xx   ← 0x0004 号线圈,FF00=吸合
关继电器:01 05 00 04 00 00 xx xx   ← 0000=断开
```

成功时从站**原样回显**请求帧(8 字节),见 `process_response` 里 `output_value == 0xFF00` 的判断——这就是你代码里 `modbus.sendModbusCommand(1, 0x05, 0x0004, 0xFF00, {0})` "打开输出5"发出去的那一帧。

### 0x06 写单个寄存器

```
请求:01 06 00 01 00 03 xx xx     ← 把 0x0001 号寄存器写成 3
响应:01 06 00 01 00 03 xx xx     ← 原样回显
```

### 0x10 写多个寄存器

```
请求:01 10 00 01 00 02 04 00 0A 01 02 xx xx
      地址0x0001  数量2  字节数4  值1:0x000A  值2:0x0102
响应:01 10 00 01 00 02 xx xx     ← 只回"起始地址+数量",不带数据
```

### 异常响应:功能码 + 0x80

从站拒绝执行时,把功能码**加 0x80** 返回,跟一个异常码:

```
请求:01 03 00 00 07 00 xx xx     ← 请求读 7 个?越界了
响应:01 83 02 xx xx              ← 83=0x03+0x80,02=非法数据地址
```

常见异常码:`01` 非法功能、`02` 非法数据地址、`03` 非法数据值、`04` 从站故障。
`parse_response()` 开头那句 `if result.function_code > 0x80` 就是在抓这个。

## 5. CRC16:两字节"防串号"校验

发送方把地址+功能码+数据整段做 CRC16 运算,得到 2 字节校验码附在帧尾;接收方对收到的内容重算一遍,不一致就丢帧(线路干扰、波特率不匹配都会导致不一致)。

你不需要懂多项式和查表细节——`crc16.lua` 已经实现了,记住两条使用规则即可:

```lua
local payload = string.char(slaveId) .. pdu        -- 地址+功能码+数据
local crc = crc16.check_crc16(payload)             -- 返回的字符串:低字节在前
local adu = payload .. crc                         -- 拼上就是完整帧
```

校验收帧:`crc16.check_crc16(前N-2字节) == 最后2字节`,即 `verify_response_crc()` 的逻辑。

## 6. 对照你的 modbus.lua:一张图看懂分工

```
sendModbusCommand()                ←── 发方向:你调它,它组帧发出
   ├── 组 PDU:功能码 + 地址 + 数据(大端)
   ├── crc16.check_crc16() 补 CRC
   └── uart.send(uart_no, adu)

parse_modbus()                     ←── 收方向:10ms 任务轮询
   ├── uart.receive 攒字节进 buffer
   ├── 状态机:按功能码推算期望帧长(0x03/04 要先看字节数字段才能定长)
   ├── CRC 校验
   └── process_response()
         └── parse_response():按功能码拆出寄存器值/线圈状态
               └── 业务分发:0x04 读回的故障位 → 跳报警页/控继电器
```

你项目里的一句完整调用示例:

```lua
modbus.sendModbusCommand(1, 0x04, 0x0000, 0x0001, {0})
-- 发出帧:01 04 00 00 00 01 xx xx
-- 意思:1 号站,读 1 个输入寄存器,从 0x0000 开始
-- 回应进入 parse_modbus → process_response → data[1] 就是那个寄存器的值
```

## 7. 新手最常踩的 6 个坑

1. **大端序写反**:寄存器值 `0x1234` 必须先发 `0x12` 再发 `0x34`(数据高在前);
2. **CRC 字节序写反**:CRC 是**低字节在前**,和第 1 条相反;
3. **地址从 0 还是从 1**:协议帧里地址**从 0 开始**;但很多设备手册写 40001、30001 这种 5 位编号——那是文档惯例(40001=保持寄存器区第 1 个=帧里的 0x0000),对照手册时要减 1;
4. **寄存器≠字节**:1 个寄存器 16 位,读 2 个寄存器回来是 4 字节,别按字节算;
5. **0x05 的开是 0xFF00 不是 1**:写线圈"开"必须发 `FF 00`,发 `00 01` 从站会拒绝;
6. **一问一答不能并发**:上一个请求的响应没回来(或超时)之前,不要发下一个——总线上会串帧。

## 8. 学完动手:建议的验证顺序

1. 打开串口调试助手(或让 Lua `print` 帧的 HEX),手动发一帧 `01 03 00 00 00 01` 加上 CRC 算出的两字节,看从站回什么;
2. 改起始地址、改数量,观察响应的"字节数"字段跟着变;
3. 故意请求一个越界地址,观察 0x83 异常响应;
4. 最后读 `modbus.lua` 的 `sendModbusCommand`,逐行对上本文第 4 节的帧格式。
