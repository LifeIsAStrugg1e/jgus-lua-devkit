# 第零部分 如何使用本库(先看这个)

## 0.1 三种用法,按你的场景选

| 场景 | 做法 |
|---|---|
| **开一个新工程(最常用)** | 直接整体复制 `工程模板.lua` 为 `main.lua`,按第七部分清单改 VP 和业务分支。本库用来查"这段代码为什么这么写" |
| **从零搭一个骨架 / 换一套协议** | 按 0.2 的顺序把本库的块粘进新 `main.lua`,填好占位符。适合协议与上一项目差别大的工程 |
| **只想借某个套路** | 直接按目录跳到对应块(如"加减按键""页面默认值表""CRC16"),复制单块即可,注意看该块的「依赖」 |

## 0.2 拼装顺序(按块拼装时照这个顺序粘)

```
[1-1] 模块加载与串口初始化        ← 文件最顶部,所有块都依赖它产生的 uart_no
[1-2] unpack 垫片 / printk        ← 紧跟 1-1,否则发帧会报错
[1-3] 关闭 AGUS 协议              ← 初始化后调用一次
[2-1] 帧头与指令码常量
[2-2] CRC16                        ← 被发帧/收帧调用,不用自己调
[3-1] Frame 帧字段镜像             ← 先定字段,再定 2-4 的字段顺序表
[3-2] 全局状态变量
[2-4] FRAME_FIELDS + send_frame   ← 依赖 2-1 / 2-2 / 3-1 / 1-2
[4-x][5-x][6-x] 业务函数           ← 顺序不限,只要都定义在 1-4 之前
[1-4] 主循环 + 调度器              ← 必须放文件最后一行
```

> **规则**:**所有函数定义在前,主循环和 `sys.scheduler()` 在最后**。Lua 里 `local function` 只能被它之后的代码引用,顺序贴反会报 "attempt to call a nil value"。

## 0.3 占位符对照表(复制后必须全部替换)

| 占位符 | 含义 | 值从哪来 |
|---|---|---|
| `KEY_VP` / `PAGE_KEY_VP` | 按键回读 VP(屏幕写 1/2,处理完清 0) | 屏幕工程 `project.json` 的按键控件 |
| `DISP_VP` / `TIME_VP` | 数值显示 VP | `project.json` 的数值控件 |
| `TEXT_VP` | ASCII 文本区起始 VP | `project.json` 的文本控件 |
| `触控口VP` / `MAX_PAGE` | 触控使能写入口、最大页号 | 屏幕协议约定 / 页面数量 |
| `Frame.F_XXX` | 帧业务字段(全为占位名) | 你与外设的协议约定 |
| `FRAME_FIELDS` | 业务字段在帧内的字节顺序 | 协议文档,顺序不能错 |
| `CMD_READ/WRITE/TEXT` | 指令码 | 协议文档 |
| `LONG_FRAME_LEN` | 文本帧长 | 协议文档;`SHORT_FRAME_LEN` 由字段数推导,别手填 |

> ⚠️ 占位符**不是可运行的 Lua**:不替换会导致 `nil` 索引、全局变量或帧错位。粘完后全局搜一遍上面的占位符,确认一个不剩。

## 0.4 块之间的调用关系(谁调谁)

```
主循环[1-4] ──10ms──> 按键函数[4-x] ──> send_frame[2-4] ──> CRC16[2-2] + Frame[3-1]
            ──10ms──> cus_command[2-5] ──校验通过──> read_config / write_config[6-1]
                                        └─文本帧──> txt_command[6-2]
            ──1s───> Countdown[6-3] ──> time_display[5-1] / on_countdown_end(工程钩子)
Page_Switch[4-3] ──> Page_init[4-4] ──> time_display[5-1] + 跳页
use_init[5-2] ──> touch_ctrl_frame[2-3] + send_frame[2-4] + time_display[5-1]
```

# 第一部分 工程骨架(必选,直接复制)

四个块必选。前三块贴在 `main.lua` 最顶部,`1-4` 必须贴在文件最后。

## 块 1-1 模块加载与串口初始化

> **能做什么**:加载固件提供的 `sys`/`jgus`/`uart` 三个模块,打开串口,产生一个全文件共用的 `uart_no`(通道号)。
> **怎么用**:放在文件最顶部;后面所有发帧、收帧、调试输出都用这个 `uart_no`,不要重复 `require`。
> **依赖**:无。**要改**:`115200, 8, 1, 0`(波特率/数据位/停止位/校验),按外设实际参数调。

```lua
-- ===== 必选:模块加载与串口初始化(放文件最顶部) =====
local sys = require("sys")      -- 任务框架:taskInit / wait / scheduler
local jgus = require("jgus")    -- 屏幕读写:vp_read / vp_write / screen_set_page
local uart = require("uart")    -- 串口:init / send / receive
local uart_no = uart.get_default_index()   -- 默认通道号,后续所有块共用

-- 初始化 UART(必选;波特率/数据位/停止位/校验按工程改)
-- uart.init(通道, 波特率, 数据位, 停止位, 校验) 返回 1 表示成功
local ok = uart.init(uart_no, 115200, 8, 1, 0)
if ok ~= 1 then
    print("Failed to initialize UART")   -- 失败要能看到,否则后面全是静默超时
end
print("UART init result:", ok)
```

## 块 1-2 兼容垫片与调试输出

> **能做什么**:① 补上 Lua 5.4 移除的全局 `unpack`(发帧函数依赖它);② 提供 `printk` 作为真机可用的串口调试输出。
> **怎么用**:紧跟 1-1 粘贴,不用主动调用;调试时 `printk("state=" .. tostring(v))`,用串口助手/抓包看。
> **依赖**:1-1 的 `uart_no`。**要改**:无。
> **可跳过吗**:不能跳过垫片;只用 `print` 且运行环境是 Lua 5.1 时可以不要 `printk`。

```lua
-- ===== 必选:兼容垫片(Lua 5.4 已移除全局 unpack) =====
-- 不加这一句,string.char(unpack(buffer)) 会报 "attempt to call a nil value"
if not unpack then
    unpack = table.unpack
end

-- 可选但强烈建议:把字符串直接发到串口(真机上 print 通常看不到)
-- 用法:printk("Frame cmd=" .. string.format("%02X", cmd))
function printk(str)
    uart.send(uart_no, str)
end
```

## 块 1-3 关闭屏幕内置 AGUS 协议

> **能做什么**:关掉屏幕固件自带的 AGUS 协议收发,把串口让给自定义协议。
> **怎么用**:初始化之后、启动任务之前调用一次。
> **依赖**:1-1 的 `jgus`。**要改**:无。
> **不需要时**:若工程改用屏幕内置协议(不做自定义帧),整块删掉,第二部分也可跳过。

```lua
-- ===== 必选(用自定义协议时):关闭屏幕内置 AGUS 协议通讯 =====
-- 不关的话屏幕固件也在收帧,自定义帧会被吃掉或错乱
jgus.disable_serial_receive()
```

## 块 1-4 双任务主循环 + 调度器

> **能做什么**:起两个并行任务——10ms 主任务轮询按键和串口,1s 任务做计时;最后启动调度器让整个程序跑起来。
> **怎么用**:**必须放文件最后**。`while true` 里按需增删按键函数调用,函数名要对得上前面定义的块。
> **依赖**:`use_init`(5-2)、`cus_command`(2-5)、`Countdown`(6-3) 等函数都已定义。
> **要改**:主任务里的函数列表、`sys.wait(10)` / `sys.wait(1000)` 节拍(计时节拍决定倒计时精度)。

```lua
-- ===== 必选:任务与主循环(放文件最后,之前所有函数必须已定义) =====
use_init()  -- 上电初始化(块 5-2),只跑一次

-- 主任务:10ms 一轮,负责"轮询按键 + 收串口帧"
sys.taskInit(function()
    while true do
        -- TODO: 在这里挂各按键配置函数(块 4-x),例:
        -- AddSub_Key_Config(KEY_VP, DISP_VP, get, set, 1, 5, 2)
        -- Page_Switch_Config()
        cus_command()      -- 必选:串口收帧(块 2-5),不要放到慢任务里
        sys.wait(10)       -- 必选:让出 CPU,否则其他任务饿死
    end
end)

-- 慢任务:1s 一跳,负责计时类工作
sys.taskInit(function()
    while true do
        Countdown()        -- 块 6-3;没有倒计时的工程可换成别的周期任务或删掉
        sys.wait(1000)
    end
end)

sys.scheduler()            -- 必选:启动调度器,必须是文件最后一行
```

# 第二部分 自定义协议基础(必选,直接复制)

对应"A5 5A 帧头 + CRC16 + 变长业务帧 + 文本帧"这套通信框架,与业务字段含义无关,可直接复制。

## 块 2-1 帧头与协议常量(按你的协议改)

> **能做什么**:把帧头、指令码集中定义,避免魔法数字散落在各处。
> **怎么用**:放 1-1 之后、所有用到常量的块之前。
> **依赖**:无。**要改**:**全部**——按你与外设约定的帧头和指令码填。

```lua
-- ===== 必选:协议常量(全部按新工程协议改) =====
local FRAMER_HEADH = 0xA5    -- 帧头高字节
local FRAMER_HEADL = 0x5A    -- 帧头低字节

local CMD_READ  = 0xAF       -- 读指令码:外设来读当前状态
local CMD_WRITE = 0xFA       -- 写指令码:外设下发配置 / 本端上报变更
local CMD_TEXT  = 0x55       -- 文本指令码:ASCII 显示帧
```

## 块 2-2 CRC16 校验(Modbus 标准多项式 0xA001)

> **能做什么**:算一段字节数组的 CRC16,供发帧时附加、收帧时验证。
> **怎么用**:不用自己调用,`send_frame`(2-4) 和 `cus_command`(2-5) 会调它。
> **依赖**:无。**要改**:通常不用改;仅当外设用别的初值/多项式时改 `0xFFFF` / `0xA001`。

```lua
-- ===== 必选:CRC16(被 2-4 / 2-5 调用,无需手工调用) =====
-- data:字节数组(Lua 索引从 1 开始);len:参与校验的字节数(不含 CRC 本身)
local function Calculate_CRC16(data, len)
    local Reg_CRC = 0xFFFF                    -- 初值,按协议改
    for i = 1, len do
        Reg_CRC = Reg_CRC ~ data[i]          -- 逐字节异或
        for j = 1, 8 do                      -- 逐位右移
            if (Reg_CRC & 0x0001) ~= 0 then
                Reg_CRC = (Reg_CRC >> 1) ~ 0xA001   -- 多项式,按协议改
            else
                Reg_CRC = Reg_CRC >> 1
            end
        end
    end
    return Reg_CRC
end
```

## 块 2-3 触控使能/禁止帧(生成函数版)

> **能做什么**:生成"允许/禁止某页开始按键"的原始帧,用来做权限联动(如刷卡后才能启动)。
> **怎么用**:需要禁用/开放某页按键时调一次,结果交给 `jgus.vp_write_data`;常见位置是 `use_init`(5-2) 和 `write_config`(6-1) 的联动分支。
> **依赖**:1-1 的 `jgus`。**要改**:页号参数、触控口 VP(`0x00B0`)、以及帧格式(若屏幕协议不同)。
> **不需要时**:工程没有"按键禁用/权限"需求就整块跳过。

触控帧格式 `A5 5A <页号> 0005 01 <1使能/0禁止> 00`。用生成函数而不是手抄常量,页号不会抄错:

```lua
-- ===== 可选:生成某页触控按键的允许/禁止帧 =====
-- page:页号;enable:true 允许 / false 禁止
local function touch_ctrl_frame(page, enable)
    return string.char(0xA5, 0x5A, page, 0x00, 0x05, 0x01,
                       enable and 1 or 0, 0x00)
end

-- 用法(示例,不要原样复制进正式代码):
-- jgus.vp_write_data(touch_ctrl_frame(1, false), 0x00B0, 4)  -- 禁止 1 页按键
-- jgus.vp_write_data(touch_ctrl_frame(3, true),  0x00B0, 4)  -- 允许 3 页按键
```

## 块 2-4 读/写帧发送(字段顺序表驱动)

> **能做什么**:把 `Frame` 里的业务字段按 `FRAME_FIELDS` 顺序打包成帧、算 CRC、发到串口。状态有任何变化就调它上报。
> **怎么用**:`send_frame(CMD_WRITE)` 上报变更 / 应答外设写;`send_frame(CMD_READ)` 回读帧;调用点通常在按键块(4-x)、`write_config`(6-1)、`use_init`(5-2)。
> **依赖**:2-1(常量)、2-2(CRC)、3-1(Frame)、1-2(unpack 垫片)。
> **要改**:`FRAME_FIELDS` 的字段名与顺序(=协议字段顺序),以及 3-1 里对应的字段定义;两边必须一致。

帧结构 `A5 5A <指令码> <业务字段...> CRC高 CRC低`。换协议只改下面这张表:

```lua
-- ===== 必选:业务字段在帧内的顺序(按协议填,顺序不能错) =====
-- 字符串要和块 3-1 里 Frame 的字段名一一对应;数量决定帧长
local FRAME_FIELDS = {
    -- "F_CMD", "F_PAGE", "F_KEY", "F_VALUE", "F_TIME1", "F_TIME2", "F_TIME3", ...
}

-- 组帧并发送:cmd 传 CMD_READ 或 CMD_WRITE
local function send_frame(cmd)
    local buffer = { FRAMER_HEADH, FRAMER_HEADL, cmd }   -- 前 3 字节:帧头 + 指令码
    for i, name in ipairs(FRAME_FIELDS) do
        buffer[3 + i] = Frame[name] or 0       -- 从帧镜像取值;缺字段按 0 处理
    end
    local n = #buffer                           -- 业务字段长度(帧长由字段数推导)
    local value = Calculate_CRC16(buffer, n)
    buffer[n + 1] = value >> 8                 -- CRC 高字节在前
    buffer[n + 2] = value & 0xFF
    uart.send(uart_no, string.char(unpack(buffer)))   -- 需要 1-2 的 unpack 垫片
end

-- 用法(示例):
-- send_frame(CMD_WRITE)   -- 参数变化后上报
-- send_frame(CMD_READ)    -- 应答外设的读请求
```

## 块 2-5 接收状态机(逐字节收帧 + CRC 验证)

> **能做什么**:逐字节收串口数据,找帧头、按帧长分发、校验 CRC,把合法帧交给业务函数处理。
> **怎么用**:在 1-4 的 10ms 主任务里每轮调一次 `cus_command()`;**不要**放到 1s 慢任务(会丢字节)。
> **依赖**:2-1(指令码)、2-2(CRC)、2-4(FRAME_FIELDS 推帧长)、6-1(read_config/write_config)、6-2(txt_command)。
> **要改**:`LONG_FRAME_LEN`(文本帧长)、溢出上限 256、`reg_write` 应答(协议不需要就删)。

流程:帧头 `A5 5A` 同步 → 短帧走 CRC 校验 → 长帧走文本 → 溢出保护:

```lua
-- ===== 必选:接收状态机(由 1-4 主任务每 10ms 调用一次) =====
-- 指令码常量见块 2-1;帧长由字段数量推导,别写死
local SHORT_FRAME_LEN = 3 + #FRAME_FIELDS + 2   -- 帧头3 + 业务字段 + CRC2
local LONG_FRAME_LEN  = 206                     -- 文本帧长(按协议改)

local cmdbuf = {}       -- 收帧缓冲区
local cmdcount = 0      -- 已收字节数
local cmdflags = 0      -- 0=未同步帧头,1=已同步

local function cus_command()
    local ret, data = uart.receive(uart_no, 1)   -- 每次读 1 字节
    while ret > 0 do                             -- 把本次积压的字节全部收完
        cmdbuf[cmdcount + 1] = string.byte(data) -- Lua 索引从 1 开始
        cmdcount = cmdcount + 1

        if cmdcount >= 256 then          -- 必选:溢出保护,丢弃重来
            cmdcount = 0
            cmdflags = 0
            break
        end

        if 0x01 == cmdflags then  -- 已同步帧头
            if cmdcount == SHORT_FRAME_LEN then
                local value = Calculate_CRC16(cmdbuf, SHORT_FRAME_LEN - 2)
                -- 高低字节序都接受,兼容对端差异
                if ((cmdbuf[SHORT_FRAME_LEN - 1] == (value & 0xFF) and
                     cmdbuf[SHORT_FRAME_LEN]     == (value >> 8)) or
                    (cmdbuf[SHORT_FRAME_LEN - 1] == (value >> 8) and
                     cmdbuf[SHORT_FRAME_LEN]     == (value & 0xFF))) then
                    -- 校验通过 → 按指令码分发给业务函数
                    if cmdbuf[3] == CMD_READ then
                        read_config(cmdbuf)          -- 块 6-1
                    elseif cmdbuf[3] == CMD_WRITE then
                        write_config(cmdbuf)         -- 块 6-1
                        -- jgus.reg_write(0x02, 10)  -- 可选:应答屏幕,协议需要时别漏
                    end
                    cmdcount = 0                    -- 一帧处理完,复位等下一帧
                    cmdflags = 0
                end
            elseif cmdcount >= LONG_FRAME_LEN then
                if cmdbuf[3] == CMD_TEXT then
                    txt_command(cmdbuf)             -- 块 6-2
                    cmdcount = 0
                    cmdflags = 0
                end
            end
        else  -- 尚未同步,找帧头 A5 5A
            if (cmdcount == 2) and (cmdbuf[1] == 0xA5) and (cmdbuf[2] == 0x5A) then
                cmdflags = 0x01
            elseif (cmdcount == 1) and (cmdbuf[1] == 0xA5) then
                -- 收到半个帧头,继续等下一个字节
            else
                cmdcount = 0                        -- 噪声,丢弃
            end
        end

        ret, data = uart.receive(uart_no, 1)     -- 继续读下一字节
    end
end
```

# 第三部分 帧字段镜像与全局状态(必选,填占位符)

> **注意**:具体项目用什么样的结构体、有哪些字段,是**项目专属设计**。上一项目的 `TREATMENT_T`/`TreatmentTable`(Voice/Language/FunctionKey/Minutes/Seconds 等 13 字节帧字段)属于实例,见 `工程模板.lua`。本库只给通用的"帧字段镜像表"套路,字段名全是占位符。

## 块 3-1 帧字段镜像表(通用)

> **能做什么**:把帧里的业务字段集中到一张表,按键、收帧、上报都只读写它,状态不散落。
> **怎么用**:所有块通过 `Frame.F_XXX` 读写;**字段名必须同时写进 2-4 的 `FRAME_FIELDS`**,否则发帧时取不到值(会被填 0)。
> **依赖**:2-4。**要改**:字段名、数量、初值,全部按协议定。
> **可简化**:单实例工程一张普通 table 就够,不必用 metatable 造"类"。

```lua
-- ===== 必选:帧业务字段镜像(字段名全为占位符,按你的协议改) =====
-- 用法:Frame.F_VALUE = 新值;send_frame(CMD_WRITE) 就会把它带出去
local Frame = {
    F_CMD    = 0,   -- 指令/操作码(占位,按协议改)
    F_PAGE   = 0,   -- 页面/区域号
    F_KEY    = 0,   -- 参数/控件号
    F_VALUE  = 0,   -- 参数值
    F_REMAIN = 0,   -- 剩余时间(秒);无计时的工程删掉,并同步删 5-1 / 6-3
    -- ... 其他业务字段按协议加(记得同步加进 FRAME_FIELDS)
}

-- 可选:需要"类/实例"风格时再套 metatable;单实例用上面这张表即可
```

# 第四部分 通用交互模式(填占位符)

> 本部分是交互套路,占位符替换成自己工程的 VP。具体实例(实际 VP、启停/NFC 等联动)看 `工程模板.lua` 的 `Switch_Key_Config`、`ZhuangT_Key_Config` 等。

## 块 4-1 通用"加减按键"模板(最常用,一行注册一个键)

> **能做什么**:一个函数搞定所有"加/减"类按键(模式、强度、时间档位……),含范围钳制、刷显示、上报、清按键。原来要写六个近乎重复的函数。
> **怎么用**:① 复制函数定义;② 在 1-4 主任务里为每个按键写一行注册(见下方示例);③ 新增按键只加一行,不改函数。
> **依赖**:2-4(`send_frame`/`CMD_WRITE`)、3-1(`Frame.F_KEY/F_VALUE`)、3-2(被 get/set 读写的变量)。
> **要改**:`vp_key`/`vp_disp`/`min`/`max`/`fkey` 五个注册参数;约定 `1=减 / 2=加` 若屏幕相反请对调两个 if。

```lua
-- ===== 强烈推荐:加减按键通用模板 =====
-- 约定:屏幕按键触发后向按键回读 VP 写 1=减 / 2=加,处理完清 0
-- vp_key:  按键回读 VP        vp_disp: 数值显示 VP
-- get/set: 变量读写闭包        min/max: 数值范围
-- fkey:    上报帧里的参数/控件号
local function AddSub_Key_Config(vp_key, vp_disp, get, set, min, max, fkey)
    if 0 ~= jgus.vp_read(vp_key) then            -- 有按键才处理,避免空转
        local v = get()
        if 2 == jgus.vp_read(vp_key) then       -- 加(带上限钳制)
            v = (v >= max) and max or (v + 1)
        end
        if 1 == jgus.vp_read(vp_key) then       -- 减(带下限钳制)
            v = (v <= min) and min or (v - 1)
        end
        set(v)                                  -- 写回变量
        Frame.F_KEY = fkey                      -- 帧镜像:哪个参数变了
        Frame.F_VALUE = v                       -- 帧镜像:变成了什么
        jgus.vp_write(vp_disp, v)               -- 刷新屏幕显示
        send_frame(CMD_WRITE)                   -- 上报外设(块 2-4)
        jgus.vp_write(vp_key, 0)                -- 必选:清零,否则同一次按键会反复触发
    end
end

-- 用法:在主循环里注册(示例,把占位符换成真实值)
-- AddSub_Key_Config(0xKEY_VP, 0xDISP_VP,
--     function() return ModeValue end,       -- get
--     function(v) ModeValue = v end,         -- set
--     1, 5, 2)                              -- min, max, 参数号
```

# 第八部分 坑位记录

踩过的坑,新工程开工前过一遍:

| # | 坑 | 说明 |
|---|---|---|
| 1 | Lua 5.4 无全局 `unpack` | 必须加 `unpack = table.unpack` 垫片,否则 `string.char(unpack(...))` 报错 |
| 2 | Lua 索引从 1 开始 | `cmdbuf[cmdcount + 1]`、帧字段全部从 1 数,C 背景极易踩 |
| 3 | CRC 字节序 | 发送高字节在前;接收校验做了高低序双兼容 |
| 4 | 页面/范围判断用 `or` 恒真 | `x > 0 or x < 4` 对任何数都成立,范围判断必须用 `and` |
| 5 | 未声明的变量是全局变量 | Lua 忘写 `local` 不报错,变量悄悄变全局,读写错乱难排查(上一项目 `MpaValue` 就踩过,见模板【修正】) |
| 6 | 按键 VP 处理完必须清 0 | 不清零同一按键状态会反复触发;清零也是"处理完成"的标志 |
| 7 | 函数内 `local ticks` 计时无效 | 每次调用都重新初始化,相关分支成死代码;计时靠外层任务 `sys.wait()` 驱动 |
| 8 | `reg_write(0x02, 10)` 应答不能漏 | 收到外设写帧后要给屏幕应答/复位标志(协议需要时),漏了屏幕会卡状态 |
